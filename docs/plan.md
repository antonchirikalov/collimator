# collimator — компилятор pipeline.yaml → Dynamic Workflows

Коллиматор сводит рассеянные лучи в один параллельный пучок: на входе одна декларация, на
выходе — параллельный фан-аут агентов. Линия названий продолжается: spectra → refract →
collimator. Пакет `collimator/`, команда `collimate`.

## Контекст

refract — личный инструмент для подготовки документов (дизайны решений, требования) с
иллюстрациями через figgybanana. За время его разработки Claude Code забрал себе почти всё,
что делает наш движок: параллельный фан-аут, изоляцию контекста, ретраи, структурированный
вывод со схемой, оркестрацию скриптом (Dynamic Workflows), хуки, кастомных подагентов.

Разбор в `docs/analysis-native-claude-vs-refract.md` (там же цифры и ссылки на
документацию) показал: нативно не хватает только трёх вещей — прогона дольше сессии,
человека посреди прогона и гейтов по содержимому. Первое владелец согласился считать
допустимой потерей, второе закрывается разбиением на стадии, третье — нашим же скриптом
проверок.

Решение: **движок не нужен, нужен компилятор**. `pipeline.yaml` остаётся единственным
источником правды, из него генерируются скрипт воркфлоу и определения подагентов. Модель
скрипты не пишет — их пишет наш генератор, поэтому состав и число агентов заданы YAML, а
сгенерированный скрипт коммитится и диффится.

Ключевой факт про Agent SDK, снимающий альтернативу: SDK требует авторизации ключом API
(«сторонним разработчикам не разрешено использовать вход через claude.ai или лимиты
подписки для их продуктов, включая агентов на Claude Agent SDK»), а Dynamic Workflows
исполняются внутри Claude Code на уже имеющейся корпоративной подписке. Ключ не нужен.

Отдельно решено: **новый репозиторий**, refract замораживается как источник промптов,
типов, шаблонов и валидатора. Причина не в объёме кода (хотя умирает 78% движка и 76%
тестов), а в документах: `CLAUDE.md` объявляет `SPEC.md` источником правды, а это 1277
строк про исполнение — планировщик, леджер, восстановление. От инвариантов I1–I10
переживают полтора.

## Этап 0 — минимальная проверка, до всякого компилятора

Цель: одним прогоном снять все неизвестные, от которых зависит устройство генератора.
Скрипт пишется **руками**, коротким, и потом выбрасывается.

Что проверяется и что делаем, если не подтвердится:

| Неизвестное | Как проверяем | Если нет |
|---|---|---|
| Сохранённый скрипт, написанный нами, запускается как `/probe` | файл `.claude/workflows/probe.mjs`, вызов `/probe` | запуск через инструмент `Workflow` по `scriptPath` |
| `agentType` подхватывает наше определение агента | `agent(…, {agentType: 'probe-researcher'})` | генератор вставляет промпт целиком в вызов, без переиспользования |
| Агент воркфлоу дотягивается до Tavily MCP | ресерчер обязан вернуть три источника по теме | объявить MCP на уровне проекта (`.mcp.json`), фронтматтер оставить как ограничение |
| Артефакты пишутся в каталог прогона | ресерчер пишет `<run>/sources.md`, схема возвращает путь | пересмотреть конвенцию каталогов |
| Гейт работает отдельной стадией | дешёвый агент запускает `tools/gate.py` и возвращает его JSON по схеме | гейт внутри агента-производителя, проверка сверху |
| Петля гейт-ретрая с обратной связью | искусственно завышенный порог, один круг исправления | цикл в промпте вместо цикла в скрипте |
| Каталог прогона приходит через `args` | `/probe` с путём каталога | путь константой в скрипте, генерировать на каждый прогон |

Проверка идёт **уже в новом репозитории** — заодно проверяется и раскладка. Артефакты этапа:

- `.claude/workflows/probe.mjs` — около 60 строк;
- `.claude/agents/probe-researcher.md` — фронтматтер `tools`, `mcpServers`, `model` + тело;
- `tools/gate.py` — **настоящий**, не выбрасывается: `--file`, `--max-length`,
  `--min-prose`, `--forbid` (повторяемый), `--min-entries`; печатает
  `{ok, problems, measures}` тем же форматом, что сейчас пишет движок в `gate_report.json`;
- `docs/probe-findings.md` — что подтвердилось, что нет.

Ограничения рантайма, которые скрипт обязан уважать (иначе прогон не стартует): `meta` —
чистый литерал без переменных и вызовов; `import()` запрещён; `Date.now()`, `new Date()` и
`Math.random()` недоступны; у скрипта нет доступа к файловой системе и шеллу.

Объём: полдня.

## Этап 1 — компилятор

Новый репозиторий. Переносится из refract как есть, вместе с тестами:

| Из refract | Строк | Зачем |
|---|---|---|
| `refract/graph.py` | 1055 | загрузка и валидация графа, все коды ошибок; зависит только от моделей и реестра |
| `refract/registry.py` | 498 | реестр типов артефактов, проверка JSON-схем |
| `refract/models/` (кроме `ledger.py`) | ~640 | форматы `pipeline.yaml`, `agent.yaml`, типов |
| `refract/prompt.py` | 278 | **уже** генерирует хвост промпта из контракта портов (I5) — ровно то, что нужно генератору |
| `tests/test_graph_validation.py`, `test_registry.py`, `test_models.py`, `test_templates.py` | ~3100 | покрытие переносимого |
| `library/` целиком | ~2200 | 22 промпта, 22 `agent.yaml`, типы, 7 шаблонов — главный актив |

Не переносится: `scheduler.py`, `cli.py`, `api/`, `runtime/`, `steps.py`, `metanodes.py`,
`explain.py`, `state.py`, `snapshot.py`, `artifacts.py`, `patch.py`, `builtins/` и их тесты.

Новый код:

- `emit_agents.py` — `agent.yaml` + `prompt.md` → `.claude/agents/<slug>.md`. Отображение
  `needs` в фронтматтер: `read`→`Read`, `edit`→`Write, Edit`, `bash`→`Bash`,
  `webfetch`→`WebFetch`, `vision`→`Read`, `"mcp:<сервер>"`→ `mcp__<сервер>` в `tools` плюс
  `<сервер>` в `mcpServers`. Пять агентов из 22 требуют MCP: три Tavily, один pdf-reader,
  `source_finder` оба;
- `emit_workflow.py` — узлы в конструкции скрипта:

  | Узел | Конструкция |
  |---|---|
  | `type: agent` | `agent(prompt, {agentType, schema, model, label, phase})` |
  | `map` / `map_over` | `pipeline(items, …)`, `.filter(Boolean)`, проверка `min_ok` |
  | `loop` | `for` с вердиктом через `schema`; **неисполненный `revise` обязан попасть в файл и в `log()`** |
  | `select` | `parallel()` кандидатов + агент-судья со схемой |
  | `gate_rules` | стадия с `tools/gate.py` + цикл ретраев с инжекцией `problems` |
  | `checkpoints` | граница между сегментами: отдельный файл скрипта на сегмент |
  | `params.model` | `{model: …}` у вызова |
  | `meta.phases` | из id узлов, чтобы в `/workflows` были наши имена |

- `cli.py` — `collimate build <pipeline.yaml> --workflows <dir> --agents <dir>`; печатает
  число агентов на прогон, чтобы сверять с ориентиром размера (по умолчанию `medium` — менее
  15):

  ```
  $ collimate build library/templates/explainer_article.yaml
    validated  explainer_article.yaml  (0 errors)
    agents     6 → .claude/agents/
    segments   3 → /article-research /article-write /article-figures
    agents per run: 9 + 8 (map) + 4 (figures) = 21
  ```

Гарантии, которые переезжают из движка в генератор: валидация до генерации (не
скомпилируется то, что не проходит наш валидатор), детерминированность вывода (один YAML —
один и тот же скрипт, проверяется тестом на golden-файл), явность политик (молчаливый проход
петли невозможен, потому что генератор его не эмитит).

Объём: 3–4 дня.

## Этап 2 — перенос конвейера и сверка

Первым — `explainer_article.yaml` (158 строк), единственный проверенный живым прогоном:
есть с чем сравнивать. Он же содержит всё сложное: петля с критиком, два чекпойнта, `map` по
восьми источникам, иллюстратор с внешним CLI.

Сегменты по чекпойнтам дают три команды: `/article-research`, `/article-write`,
`/article-figures`. Это заодно снимает проблему размера — 23 шага одним воркфлоу упираются в
ориентир.

Сверка с `attn-article/runs/run_20260811_121834`: длина финального текста (было 13 662
знака при брифе 8–12 тысяч), число и предметность замечаний критика (было 11 за три круга),
четыре фигуры с манифестом, стоимость (было $37,31, из них 57% петля письма).

Объём: 2 дня.

## Передача работы между сессиями

Определения агентов и воркфлоу обнаруживаются **при старте сессии**: файл, созданный
посреди сессии, в её реестр не попадает. Отсюда порядок.

**В этой сессии** (контекст про пробник и откаты держится здесь): создать репозиторий и все
файлы, `git init`, первый коммит. Пробник **не запускать** — эта сессия его агента не
увидит. Скопировать план в `collimator/docs/plan.md`: `~/.claude/plans/` привязан к машине и
к id сессии, репозиторий надёжнее. Добавить `docs/handoff.md` — семь неизвестных, их откаты
и одна команда запуска.

**В новой сессии** с рабочим каталогом `collimator`: прочитать `docs/plan.md`, запустить
`/probe <каталог прогона>`, заполнить `docs/probe-findings.md`. MCP наследуются — проверено,
`tavily-remote`, `pdf-reader` и `ss-gateway` объявлены глобально в `~/.claude.json`, а не
на проект.

Резюме чата не требуется: передача идёт файлами. Эта сессия остаётся доступной через
`/resume`, если понадобятся детали разбора.

## Проверка результата

1. **Этап 0**: `/probe <каталог>` завершается, в каталоге лежит файл от ресерчера с тремя
   источниками, найденными через Tavily; в логе прогона видно, что гейт срабатывал и что
   круг исправления был; `docs/probe-findings.md` заполнен.
2. **Этап 1**: `pytest` на перенесённых тестах зелёный; `build` на всех семи шаблонах из
   `library/templates/` не падает; golden-тест на детерминированность вывода; сгенерированные
   определения агентов содержат `mcp__tavily-remote` ровно у тех трёх агентов, у которых
   `needs` его называет.
3. **Этап 2**: три команды проходят на той же статье; финальный текст ≤ 14 000 знаков (гейт),
   `UNRESOLVED.md` либо отсутствует, либо перечисляет незакрытые замечания явно; четыре PNG
   и манифест; итоговая стоимость сопоставима с $37 или ниже.

## Риски

- **`mcpServers` у агента внутри воркфлоу.** Для коллег в командах этот фронтматтер явно
  игнорируется; про агентов воркфлоу прямого утверждения в документации нет. Этап 0 нужен
  ровно поэтому.
- **Потеря прогона при выходе из сессии** принята как допустимая. Смягчение: короткие
  сегменты и много мелких агентов вместо одного длинного — при возобновлении кэш обрывается
  на первом незавершённом агенте, и всё, что стартовало после, считается заново.
- **Окружение внешнего CLI.** `PAPERBANANA_BIN` и три `SS_GATEWAY_*` объявить в `env` в
  `.claude/settings.json` нового проекта. Пять из двенадцати провалов прошлого прогона были
  про это.
- **Компилятор может оказаться избыточным** для семи шаблонов личного инструмента. Решение
  принимается после этапа 0: если руками написанный сегмент читается лучше сгенерированного,
  честнее оставить рукописные скрипты и не тащить 2470 строк валидатора.

## Раскладка нового репозитория

`~/Documents/agents/collimator/` — отдельный репозиторий, `refract-claude` не трогаем.

```
collimator/
  collimator/
    graph.py            ← из refract, без изменений
    registry.py         ← из refract, без изменений
    prompt.py           ← из refract: хвост промпта из контракта портов (I5)
    models/             ← из refract, без ledger.py
    emit_agents.py      ← новый: agent.yaml + prompt.md → .claude/agents/<slug>.md
    emit_workflow.py    ← новый: узлы → скрипт, сегменты по чекпойнтам
    cli.py              ← новый: collimate build …
  library/              ← из refract целиком: 22 агента, типы, 7 шаблонов
  tools/gate.py         ← из этапа 0
  tests/                ← перенесённые четыре набора + тесты генератора
  .claude/
    agents/             ← ГЕНЕРИРУЕТСЯ, в git попадает как результат сборки
    workflows/          ← ГЕНЕРИРУЕТСЯ
    settings.json       ← env: PAPERBANANA_BIN, три SS_GATEWAY_*
  docs/                 ← probe-findings.md, перенесённый разбор грабель
  CLAUDE.md             ← своя: «мы генерируем для Claude Code, агентов сами не запускаем»
```

Сгенерированное коммитится: тогда diff показывает, что именно поменялось в оркестрации при
правке YAML, и это же служит golden-тестом на детерминированность.

`CLAUDE.md` нового проекта не наследует инварианты refract: I3, I7, I9, I10 относились к
рантайму, которого нет. Переживают I5 (инструкции из контракта — теперь работа генератора) и
I6 (агент не производит коллекций — теперь `pipeline()` в скрипте). I1 обеспечивает сам
Claude Code своим хуком.
